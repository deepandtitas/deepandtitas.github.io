# Remake contracts (owned by the orchestrator — ask on BOARD.md to change anything here)

Same story, look and features as the old build (`C:\Projects\deepandtitas.github.io`, read-only reference), rebuilt so a
phone can draw it: **all imagery is drawn by one canvas renderer**. The DOM holds only the one picture canvas, text
and tap targets. Specs: `remake/SPEC/story.md` (timing, motion, poses), `remake/SPEC/visual.md` (appearance, art,
paint order, text styling), `remake/SPEC/shell.md` (website, controls, strings, tooling). Reference stills of the old
build: `remake/SPEC/reference/<lang>-<frame>.png` (half size, 540×960; `reduced/` = reduced motion).

## Why (measured on a moto g96 5G, Chrome 156)
The old picture was ~40 DOM layers, many 1080×1920 or larger: ~300 MB GPU tile memory in the wedding; Chrome ran out
of tile memory in 98% of tile assignments and drew ~1,200 layers with tiles missing per 4 s (heads blinking, holes,
the couple vanishing at a scene change). A canvas is one texture of fixed size that never has missing tiles.

## Hard rules (every agent)
1. **Frame-driven and pure.** Everything on screen is a pure function of the frame + context. No `Date`, `performance`,
   `Math.random`, timers, or module-level mutable state in `src/story`, `src/scene`, `src/render` (lint-enforced).
   Same input → identical output.
2. **Single sources of truth.** Timing only in `src/story/timeline.ts`; positions only in `src/story/layout.ts`; strings
   only in `src/content/translations.ts`; event details only in `src/content/wedding.ts`; art only via
   `src/art/manifest.ts`. No numeric frame/beat literals in `src/scene` (derive from timeline).
3. **One picture canvas.** No `<img>`, `<svg>`, CSS gradients or `will-change` imagery in the composition. The overlay
   has a FIXED set of elements for the whole story (each always mounted; hidden with `visibility`/opacity), each box
   sized to its content (never `inset: 0` / full-frame boxes).
4. **No `import.meta.env` in `src/remotion`, `src/scene`, `src/story`, `src/render`** (Remotion bundles with webpack).
5. **Asset URLs** go through `asset(base, src)` (`src/content/assets.ts`), base from the `assetBase` input prop.
6. **Never fabricate wedding details**; blank fields stay hidden. The map link opens `wedding.mapUrl` exactly.
7. **Ritual order** শুভদৃষ্টি then মালাবদল; no fire ritual, no sindoor daan.
8. **Fonts**: Anek Bangla (variable 100–800) for Bengali, Galada (single weight, `DISPLAY_WEIGHT`) for the names,
   Cormorant Garamond for English; Bengali text boxes that clip keep `BN_PAD` block padding.
9. TypeScript strict; match the code style you see; small focused modules; JSDoc on exported functions.
10. Write tests for what you build (Vitest, `tests/**/*.test.ts(x)`). Your wave is not done until
    `npm run typecheck`, `npm run lint`, `npm test` pass in the worktree.

## Interfaces

### Art manifest — `src/art/manifest.ts` (generated by `npm run art`)
```ts
export const ART = {
  "garden-far": { src: "art/garden-far.webp", x: number, y: number, w: number, h: number, bytes: number },
  // … one entry per baked image
} as const;
export type ArtName = keyof typeof ART;
```
`x, y` = top-left of the trimmed image in the piece's own design coordinates (for sprites/rig parts relative to their
origin/pivot space, for scenery relative to its plane), `w, h` its size in composition px. Same convention as the old
`art-manifest.ts`; names may be kept from the old build.

### Matrices — `src/render/mat.ts` (renderer)
```ts
export type Mat = readonly [a: number, b: number, c: number, d: number, e: number, f: number]; // canvas setTransform order
export const I: Mat;
export const mul: (m: Mat, n: Mat) => Mat;          // m · n (apply n first, then m)
export const translate: (x: number, y: number) => Mat;
export const rotate: (deg: number) => Mat;
export const scale: (sx: number, sy?: number) => Mat;
export const about: (ox: number, oy: number, m: Mat) => Mat; // translate(o) · m · translate(-o)
export const apply: (m: Mat, p: { x: number; y: number }) => { x: number; y: number };
/** CSS-like `translate(x,y) rotate(r) scale(sx·k, k)` — the sprite placement. */
export const sprite: (x: number, y: number, rotDeg: number, k: number, sx?: number) => Mat;
```

### Draw ops — `src/render/ops.ts` (renderer)
```ts
import type { ArtName } from "../art/manifest";
import type { Mat } from "./mat";
export interface Rect { x: number; y: number; w: number; h: number }
export type Paint =
  | string                                                     // CSS colour
  | { linear: [x0: number, y0: number, x1: number, y1: number]; stops: [offset: number, color: string][] }
  | { radial: [x0: number, y0: number, r0: number, x1: number, y1: number, r1: number]; stops: [number, string][] };
export interface Stroke { paint: Paint; width: number; cap?: CanvasLineCap; join?: CanvasLineJoin; dash?: number[]; dashOffset?: number }
/** A clip region with its own matrix (so it zooms with the camera): a rectangle or SVG path data, in local coordinates under m. */
export type Clip = { rect: Rect; m: Mat } | { path: string; m: Mat };
export type DrawOp =
  /** ART[art] drawn at its manifest rect (x,y,w,h) in local coordinates, under m. */
  | { kind: "image"; art: ArtName; m: Mat; alpha: number; clip?: Clip }
  /** SVG path data in local coordinates under m (fill and/or stroke). */
  | { kind: "path"; d: string; m: Mat; alpha: number; fill?: Paint; stroke?: Stroke; clip?: Clip }
  /** Circle / ellipse (cheaper than a path for glows and discs). */
  | { kind: "ellipse"; cx: number; cy: number; rx: number; ry: number; m: Mat; alpha: number; fill: Paint; clip?: Clip }
  /** Axis-aligned rectangle (washes, card backgrounds). */
  | { kind: "rect"; rect: Rect; m: Mat; alpha: number; fill: Paint; radius?: number; clip?: Clip }
  /**
   * Group opacity (SVG <g opacity> semantics): children are drawn at full alpha into a pooled offscreen canvas of
   * `bounds` (frame coordinates, rounded out) and composited with `alpha`. Use ONLY where overlapping children make
   * per-op alpha visibly wrong (e.g. the lotus fading in). `alpha >= 0.999` → children drawn directly.
   */
  | { kind: "group"; alpha: number; bounds: Rect; ops: DrawOp[] };
```
Rules: `alpha <= 0.002` → the op is skipped. Matrices are final (frame coordinates); scene code composes the camera
and parent transforms itself with `mul`. Ops are drawn in array order (back to front).

### Overlay items — `src/render/overlay.ts` (renderer defines; scenes produce)
```ts
export type OverlayItem =
  /** A line of text placed in frame coordinates; the box is sized to its content. */
  | { kind: "text"; id: string; text: string; x: number; y: number; anchor: "center" | "left" | "right";
      style: TextStyleId; opacity: number; m?: Mat; reveal?: number /* 0..1 left-to-right reveal; 1 = all */;
      /** 0..1 gold glow: textShadow `0 0 ${30·g}px rgba(233,201,126,${0.9·g})` (the card names' shimmer). */
      glow?: number }
  /** A tap target (guided hotspot / map link). Only these receive pointer events. */
  | { kind: "hotspot"; id: string; x: number; y: number; size: number; label: string; ariaLabel: string;
      labelPosition: "above" | "below"; visible: boolean; action: HotspotAction }
  | { kind: "link"; id: string; href: string; text: string; x: number; y: number; style: TextStyleId; opacity: number; visible: boolean };
export type TextStyleId = string;   // keys of TEXT_STYLES in src/render/textStyles.ts (renderer), from SPEC/visual.md
export type HotspotAction = "awakening" | "meeting" | "wedding" | "invitation";
```
The set of overlay `id`s is FIXED for the whole composition: `describeFrame` returns every id on every frame
(hidden ones with `opacity: 0` / `visible: false`). The overlay renders one element per id, keyed by id, and writes
per-frame values straight to the DOM (no React re-diff per frame), positioned in the 1080×1920 frame.

## Scene assembly (wave 2: scenes-a, scenes-b)

### Paint order (canvas, back to front) — assembled by `describeFrame` in src/scene/frame.ts
1. `paper` art, full frame (always).
2. Awakening (scenes-a `awakening(beat, ctx)`), drawn while its Sequence would be mounted (beats 0 … awakening end +
   overlap); its fade-out (old `opacity: 1 - exit` on the scene) is ONE `group` op with full-frame bounds.
3. **Camera group** — every op below gets `cam = about(CAMERA_FOCUS.x, CAMERA_FOCUS.y, scale(cameraZoom(beat)))`
   multiplied on the left (`mul(cam, m)`, also for clip matrices and overlay text `m`; hotspot x,y via `apply`):
   a. garden back (scenes-b `gardenBack`): far plane, sun warmth, path, mid plane, dusk wash, lights;
   b. meeting arch flowers (while the meeting is mounted);
   c. wedding back (scenes-b): big glow, mandap structure, gathered arch, diyas, gaze glow;
   d. **the couple** (scenes-b `couple`): ONE persistent pair for the whole meeting+wedding span from
      `couplePose(globalBeat, reduced)` — never two pairs, so nothing pops at the scene change; front figure per
      `front`;
   e. wedding front sprites: garlands, set-down leaves, the crossing petal;
   f. the ornament (scenes-a `emblemOps`) and the rising card edge (scenes-a `invitationCard`, id prefix `card-w`);
   g. garden foreground leaves (scenes-b `gardenForeground`).
4. Scene headings' gold rules (scenes-a `headings`).
5. Invitation scene (scenes-a `invitationScene`, its card with id prefix `card-i`).
6. Atmosphere: `atmosphereSprites(beat, reduced)` (petals + dust), last.
Overlay (DOM, above the canvas): headings, title/subtitle, card texts, hotspots, map link.

### Converting the old DOM/SVG/CSS to ops (exact rules)
- **CSS transform**: an element whose box top-left is B (left/top), with `transform: T` and `transform-origin: O`
  (relative to the box) maps local box coordinates by `translate(B+O) · T · translate(-(B+O))`, then `translate(B)`
  for content drawn at the box origin. A child's matrix = parent matrix · child matrix. An `<img>` with `artBox(name)`
  is the image op at the manifest rect (x,y,w,h are already B and size). Rig parts: `translate(at) · rotate(rot) ·
  scale(sx,sy) · translate(-pivot)` applied to the part's manifest rect (old partTransform with origin = pivot).
- **SVG**: `<g transform>` multiplies like CSS; `<path d>` → path op with the same d; `<circle>`/`<ellipse>` →
  ellipse op; `opacity` on an element multiplies its ops' alpha; a `<g opacity>` with overlapping children → `group`
  op; `fillOpacity`/`strokeOpacity` → rgba colour; `clipPath` → op `clip: { path, m }`.
- **CSS radial-gradient(circle at px py, …)** on a W×H box: default size farthest-corner, r = distance from
  (px,py) to the farthest corner; stop % × r → radial Paint `[px,py,0,px,py,r]`. `border-radius: 50%` boxes → ellipse
  op with that paint. **linear-gradient(180deg, …)** on a box → linear Paint from (x, top) to (x, bottom).
- Opacity < 0.002 → skip. `visibility: hidden` → no ops.
